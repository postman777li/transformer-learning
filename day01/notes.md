# Day 1：为什么 Transformer 会出现？

> 从词语顺序、记忆纸条和传话游戏出发，理解 RNN、LSTM 的局限，以及 Attention 为什么能带来不同的序列建模方式。

## 当天学习目标

- 理解语言中的顺序与上下文关系。
- 理解 RNN 的隐藏状态、串行依赖和长距离依赖问题。
- 理解 LSTM 如何通过细胞状态和门控改善记忆，以及仍然存在的局限。
- 理解 Transformer 的并行计算与直接信息交互，不提前展开 Q、K、V。

## 1. 为什么自然语言需要序列建模？

### 1.1 从简单例子开始

考虑下面两句话：

**句子 A：狗咬人。**

**句子 B：人咬狗。**

虽然两句话使用的字基本相同，但顺序不同，表达的意思完全不同。

这说明：

语言不仅由词语构成，**词语的排列顺序也会影响句子的含义。**

再看一句话：

> 我今天去学校上课。

我们可以把它看成一个序列：

```text
我 → 今天 → 去 → 学校 → 上课
```

当模型读到“学校”时，如果只知道“学校”这一个词，而不知道前面的“我、今天、去”，就无法充分理解当前上下文。

因此，处理自然语言时，模型需要考虑词语之间的顺序与上下文关系。

### 1.2 专业概念：序列建模（Sequence Modeling）

序列建模是指：

**对有顺序的数据进行建模，利用序列中不同位置的信息完成理解、预测或生成任务。**

自然语言就是一种典型的序列数据。

例如：

- 输入前面的词，预测下一个词。
- 根据上下文理解某个词的含义。
- 将一种语言的句子翻译成另一种语言。

## 2. RNN 是什么？为什么出现？

### 2.1 从一个具体例子开始

假设现在有一句话：

> 我 喜欢 吃 苹果

我们希望神经网络能够理解这句话。

一种非常自然的想法是：

**既然人类说话有顺序，那就让模型按照顺序一个词一个词地读。**

于是模型这样处理：

```text
第1步：读入“我”
       ↓
得到记忆 h1

第2步：读入“喜欢”
       ↓
结合 h1
       ↓
得到记忆 h2

第3步：读入“吃”
       ↓
结合 h2
       ↓
得到记忆 h3

第4步：读入“苹果”
       ↓
结合 h3
       ↓
得到记忆 h4
```

例如，模型读到“吃”时，不是孤立地处理这个词，而是同时参考前面形成的状态。

可以把整个过程理解成：

> 模型手里有一张不断更新的记忆纸条，每读一个新词，就结合新词和纸条上的旧信息，写出一张新的纸条。

注意：这里的“记忆”只是帮助理解的比喻。真实模型保存的是数值向量，不是直接存储中文句子。

### 2.2 专业概念：RNN

RNN 全称：

**Recurrent Neural Network（循环神经网络）**

RNN 的核心思想：

**利用前一时间步的隐藏状态与当前输入，计算当前时间步的隐藏状态。**

公式：

$$
h_t=f(x_t,h_{t-1})
$$

其中：

- $x_t$：当前时间步的输入，例如当前 token 的向量。
- $h_{t-1}$：上一时间步的隐藏状态。
- $h_t$：当前时间步更新后的隐藏状态。
- $f$：由可训练参数决定的计算过程。

一个基本 RNN 的具体形式可以写成：

$$
h_t=\tanh(W_xx_t+W_hh_{t-1}+b)
$$

其中 $W_x,W_h,b$ 是模型要学习的参数。

### 2.3 RNN 如何利用顺序？

还是刚才的例子：

```text
我 → 喜欢 → 吃 → 苹果
```

因为：

```text
h2 依赖 h1
h3 依赖 h2
h4 依赖 h3
```

所以 RNN 的信息传递关系为：

```text
h1 → h2 → h3 → h4
```

也就是说，后一步的计算需要前一步的结果。

这就是 RNN 处理顺序信息的基本方式。

## 3. RNN 存在什么问题？

RNN 主要存在两个与本课程密切相关的问题。

### 3.1 问题一：串行计算，难以充分并行

继续使用：

> 我 喜欢 吃 苹果

RNN 的计算是：

```text
我
↓
喜欢
↓
吃
↓
苹果
```

为什么不能把四步的隐藏状态同时计算出来？

因为：

```text
要算 h2，必须先得到 h1。

要算 h3，必须先得到 h2。

要算 h4，必须先得到 h3。
```

假设输入长度增加到 1000 个 token：

```text
token1 → token2 → token3 → ... → token1000
```

模型仍然需要按照时间步依次计算隐藏状态。

而 GPU 非常擅长并行矩阵运算。

RNN 在时间维度上的依赖关系限制了这种并行能力。

**专业概念：串行依赖（Sequential Dependency）**

指当前计算依赖前一个计算步骤的结果，无法将这些步骤完全独立地同时执行。

注意：RNN 并不是所有计算都不能并行，例如不同样本之间仍然可以并行。这里强调的是时间步之间的依赖。

### 3.2 问题二：长距离依赖难以学习

先看一个例子：

> 我在很多年前去过北京，后来去了很多地方，经历了很多事情……那座城市一直让我难以忘怀。

当模型处理“那座城市”时，需要联系很久以前出现的“北京”。

但 RNN 的信息传递路径可能是：

```text
北京
 ↓
h1
 ↓
h2
 ↓
h3
 ↓
...
 ↓
h100
 ↓
那座城市
```

早期信息需要经历很多次隐藏状态更新，才能影响较远位置的输出。

可以把它理解成传话游戏：

```text
第1个人 → 第2个人 → 第3个人 → ... → 第100个人
```

传递次数越多，原始信息越容易发生变化或丢失。

在真实神经网络里，长距离依赖难以学习还与反向传播过程中的梯度消失、梯度爆炸有关。

**专业概念：长距离依赖（Long-Range Dependency）**

指序列中距离较远的两个位置存在重要关系，模型需要利用远处的信息完成当前任务。

RNN 在长序列上较难稳定地学习这种关系。

## 4. LSTM 为什么出现？

### 4.1 先从 RNN 的记忆问题出发

我们已经知道：

RNN 会不断更新隐藏状态。

但如果每次都更新，早期的重要信息就可能逐渐被冲淡。

研究者开始思考：

> 能不能让模型自己决定哪些信息值得保留，哪些信息应该忘记？

例如：

> 小明出生在上海，后来去了杭州工作，期间发生了很多事情……多年以后，他依然怀念自己的家乡。

这里包含很多信息：

```text
人物：小明

出生地：上海

后来工作地：杭州

时间：多年以后
```

当模型理解“家乡”时，出生地“上海”就是特别有用的信息。

但并不是所有中间内容都有相同的重要性。

因此模型需要更灵活的记忆管理能力。

### 4.2 LSTM 的基本思想

LSTM 全称：

**Long Short-Term Memory（长短期记忆网络）**

LSTM 是 RNN 的一种改进结构。

它仍然按时间顺序处理输入，但引入了更精细的记忆控制机制。

可以理解成：

```text
普通 RNN：

旧记忆 + 新输入
       ↓
更新隐藏状态
```

```text
LSTM：

旧记忆 + 新输入
       ↓
决定忘掉什么
       ↓
决定写入什么
       ↓
决定输出什么
```

LSTM 内部的重要组成部分包括：

- Cell State：细胞状态，负责传递长期信息。
- Hidden State：隐藏状态，表示当前时间步的输出状态。
- Gate：门控机制，控制信息流动。

### 4.3 LSTM 的三个门

**第一：遗忘门（Forget Gate）**

决定旧记忆中哪些内容应该保留，哪些内容应该削弱。

例如：

```text
主角叫小明 → 保留

出生在上海 → 保留

某天的天气 → 当前任务可能不需要
```

**第二：输入门（Input Gate）**

决定当前新信息中哪些内容需要写入记忆。

例如读到：

> 小明后来搬到杭州。

模型可以决定将“杭州”相关的新信息写入记忆状态。

**第三：输出门（Output Gate）**

决定当前应该从记忆状态中输出哪些信息，形成当前隐藏状态。

例如正在判断：

> 他最怀念的城市是……

模型可能需要让与“上海”相关的信息影响当前输出。

### 4.4 LSTM 解决了什么问题？

相比普通 RNN，LSTM 通过门控机制和细胞状态，让模型能够更有效地保留重要信息。

因此：

**LSTM 缓解了普通 RNN 难以学习长期依赖的问题。**

但要注意：

LSTM 不是彻底解决了长距离依赖，而是改善了信息传递和梯度传播。

---

## 5. 为什么 LSTM 仍然存在局限？

最关键的原因：

**LSTM 仍然属于循环结构。**

虽然记忆管理更智能，但它仍然需要：

```text
token1
   ↓
token2
   ↓
token3
   ↓
token4
```

当前时间步的隐藏状态仍然依赖上一时间步。

所以：

1. 时间步之间仍然存在串行依赖。
2. 长距离信息仍然要经过多个时间步传递。
3. 不能充分发挥 GPU 在序列维度上的并行计算能力。

因此，LSTM 虽然比普通 RNN 更擅长保存长期信息，但并没有根本改变循环处理序列的方式。

## 6. Transformer 为什么出现？

### 6.1 从一个问题开始

既然 RNN 和 LSTM 都需要一个一个处理 token，那有没有一种办法：

**不必等待前一个 token 的隐藏状态，就能让所有 token 交换信息？**

例如：

> 我 喜欢 吃 苹果

传统 RNN 的处理过程：

```text
我 → 喜欢 → 吃 → 苹果
```

研究者尝试另外一种思路：

先得到所有 token 的输入向量：

```text
我      → x1

喜欢    → x2

吃      → x3

苹果    → x4
```

然后让每个 token 根据需要，从其他 token 获取信息。

例如“吃”可能需要较多地关注“苹果”：

```text
               我
               ↑
喜欢 ←─────── 吃 ───────→ 苹果
               ↓
               吃
```

假设“吃”对各个 token 的关注权重是：

```text
我      0.05

喜欢    0.20

吃      0.15

苹果    0.60
```

这些数字只是为了说明原理而假设的，并不是已经训练出来的真实结果。

这里表示：

“吃”从“苹果”获取的信息占比较高。

同时，“我”“喜欢”“苹果”也可以分别计算自己应该关注哪些位置。

### 6.2 这种方法的核心优势

**优势一：更容易并行计算**

RNN：

```text
先计算 h1
再计算 h2
再计算 h3
再计算 h4
```

Transformer：

```text
所有 token 的输入向量
          ↓
并行计算它们之间的关注关系
          ↓
各 token 得到融合上下文的新表示
```

核心原因：

当前层中一个 token 的注意力计算，不依赖同一层前一个位置已经计算完成的隐藏状态。

因此可以利用矩阵运算同时计算多个位置的注意力关系。

**优势二：更短的长距离信息交互路径**

假设句子有 1000 个 token。

RNN 中，最后一个 token 如果需要利用第一个 token 的信息，通常需要经过大量循环步骤：

```text
1 → 2 → 3 → ... → 1000
```

在允许关注全部历史位置的自注意力层中，第 1000 个 token 可以直接关注第 1 个 token；因果掩码不会阻止当前位置关注过去，但局部窗口等限制可能阻止这种连接：

```text
1 ─────────────────→ 1000
```

这意味着两个远距离位置之间可以在单个注意力层内直接发生信息交互。

需要注意：交互路径短，不代表模型必然能准确理解所有长距离关系。

### 6.3 专业概念：Self-Attention

Self-Attention（自注意力）是一种机制：

**序列中每个 token 可以根据自身与其他 token 的关系，对相关 token 的信息进行加权聚合，从而得到上下文相关的新表示。**

例如：

```text
输入：“我 喜欢 吃 苹果”

原始 token 向量
       ↓
Self-Attention
       ↓
融合上下文信息
       ↓
新的 token 表示
```

这里要区分：

- Attention 是一种信息选择和聚合机制。
- Transformer 是以 Attention 为核心，同时结合其他模块构建的模型架构。
- Transformer 不等于只有 Attention 一个计算步骤。

Day 1 暂时只需要理解 Attention 的核心直觉，不需要掌握 Q、K、V 的计算方式。

## 7. RNN、LSTM、Transformer 对比

| 对比维度 | RNN | LSTM | Transformer |
|---|---|---|---|
| 核心机制 | 循环隐藏状态 | 循环状态 + 门控记忆 | Attention |
| 处理方式 | 按时间步循环 | 按时间步循环 | 整段输入可并行计算 |
| 长距离依赖 | 较难学习 | 有所改善 | 可直接建立远距离联系 |
| 时间维度并行 | 受循环限制 | 受循环限制 | 训练时更容易并行 |
| 信息传递 | 依次传递隐藏状态 | 依次传递并控制记忆 | 注意力加权聚合 |
| 主要局限 | 遗忘与串行 | 仍然串行 | 长序列注意力计算成本较高 |

注意：表中 Transformer 的并行能力主要指训练或处理已知输入序列时。GPT 等自回归模型在生成阶段仍然需要逐 token 生成。

## 8. Day 1 必须掌握的专业术语

**Sequence（序列）**

按一定顺序排列的数据。

**Token**

文本经过分词处理后得到的基本处理单元，可以是词、子词、字符等。

**RNN（循环神经网络）**

通过循环隐藏状态处理序列的神经网络。

**Hidden State（隐藏状态）**

保存当前时间步计算所得信息的向量表示。

**Sequential Dependency（串行依赖）**

后续计算需要等待前面计算的结果。

**Long-Range Dependency（长距离依赖）**

序列中相隔较远的位置之间存在重要关系。

**LSTM（长短期记忆网络）**

通过门控机制改善长期信息保留能力的循环神经网络。

**Gate（门控机制）**

通过可学习的方式控制信息保留、写入或输出。

**Self-Attention（自注意力）**

允许 token 根据与序列内其他 token 的关系聚合信息的机制。

**Transformer**

以 Attention 机制为核心构建、能够有效并行处理序列的神经网络架构。

## 9. Day 1 常见理解误区

**误区一：RNN 完全不能处理长距离依赖。**

错误。RNN 可以利用早期信息，只是长期依赖通常较难学习。

**误区二：LSTM 完全解决了长距离依赖问题。**

错误。LSTM 显著改善了信息保留，但不能保证任意距离的信息都能准确传递。

**误区三：Transformer 完全不考虑顺序。**

错误。Transformer 不依赖 RNN 式循环来建模，但仍需要通过位置编码或位置相关机制表达顺序。

**误区四：Transformer 一次性生成所有文字。**

错误。虽然 Transformer 在训练时可以并行处理许多位置，但 GPT 等自回归语言模型生成文本时通常仍然逐 token 预测。

**误区五：Self-Attention 就是整个 Transformer。**

错误。Transformer 还包含前馈网络、归一化、残差连接等组件。

## 10. Day 1 学习检验

### 题目 1：为什么自然语言需要考虑顺序？

参考答案：

因为语言中词语的排列顺序会影响句子的含义。模型必须结合顺序和上下文关系来理解与生成文本。

### 题目 2：RNN 如何利用前面的信息？

参考答案：

RNN 通过隐藏状态，把上一时间步的信息传递到当前时间步，再结合当前输入更新隐藏状态。

### 题目 3：为什么 RNN 难以充分利用 GPU 在时间维度上的并行能力？

参考答案：

因为当前时间步的隐藏状态依赖上一时间步的计算结果，所以不同时间步之间存在循环依赖，无法全部同时计算。

### 题目 4：LSTM 相比 RNN 改善了什么？

参考答案：

LSTM 增加了细胞状态和门控机制，能够更灵活地保留、遗忘和输出信息，改善长期依赖的学习能力。

### 题目 5：LSTM 仍然没有解决什么问题？

参考答案：

LSTM 仍然依赖前一时间步的状态，无法消除时间维度上的串行计算问题。

### 题目 6：Transformer 最重要的结构变化是什么？

参考答案：

Transformer 使用 Attention，让序列中的 token 可以直接建立关系、聚合信息，而不是完全依赖逐时间步循环传递的隐藏状态。

### 题目 7：Transformer 为什么更适合并行计算？

参考答案：

因为同一注意力层中各位置的关系计算可以通过矩阵运算同时进行，不需要像 RNN 一样等待前一个时间步的隐藏状态。

## 11. Day 1 最终总结

整个发展逻辑：

```text
自然语言具有顺序和上下文关系
             ↓
需要序列建模
             ↓
RNN：一个 token 一个 token 处理
             ↓
问题：串行计算 + 长距离依赖难学习
             ↓
LSTM：增加门控机制改善长期记忆
             ↓
问题：仍然是循环串行结构
             ↓
Transformer：利用 Attention 直接建立 token 间联系
             ↓
主要优势：
1. 更容易并行计算
2. 远距离信息交互路径更短
```

**Day 1 最核心的一句话：**

Transformer 的重要突破是：**不再依赖 RNN 式逐时间步循环传递隐藏状态，而是通过 Attention，让不同位置的 token 能够直接交换和聚合信息。**
